ABSTRACT

This project focuses on the development of the Plant Disease Detection & Remedy Recommendation System using Artificial Intelligence, Computer Vision, and modern full-stack web engineering. Agriculture sustains over half of India's population; however, foliar crop diseases cause devastating annual losses of 20% to 40% of agricultural production.

The existing approach to plant disease diagnosis faces severe challenges, including subjective visual guesswork, long delays in laboratory extension testing, and digital tools that identify disease names but fail to provide practical, actionable remediation advice. To address these issues, the proposed system uses Deep Learning Computer Vision models through the Plant.id API v3 to classify crop leaf diseases from photographs and pair them with comprehensive, curated remedy plans.

The application is developed using React 18, Vite, and Tailwind CSS on the frontend, Node.js and Express.js on the backend, and MongoDB with Mongoose ODM for data storage. The AI vision component classifies botanical species and scores disease likelihoods. A custom matching service (diseaseMatchService) resolves the output against a curated knowledge base, generating symptoms, causes, organic remedies (such as neem oil and Trichoderma), chemical treatments (such as targeted fungicides and fertilizers), and prevention checklists.

The system provides key features including instant drag-and-drop leaf upload, in-memory magic-byte verification, stateless JWT authentication, scan history logging with trend visualization, and an administrative CRUD catalogue manager. The project is evaluated through 69 automated test cases (100% pass rate). The proposed application aims to improve diagnosis speed, minimize pesticide expenses, promote sustainable organic farming, and democratize agricultural advisory access for smallholder farmers.

CHAPTER 1: INTRODUCTION
1.1 Introduction to the Project

The Plant Disease Detection & Remedy Recommendation System is an intelligent, automated web platform developed to assist farmers and agronomists in identifying crop leaf diseases and obtaining actionable recovery plans. Crop diseases caused by fungi, bacteria, viruses, or nutrient deficiencies lead to massive losses in agricultural yield. This project accepts a photo of an infected leaf, runs Deep Learning Computer Vision inference via the Plant.id API, and matches the diagnosis with a curated MongoDB knowledge base to generate instant symptoms, causes, organic treatments, chemical controls, and preventive measures.

1.2 Background of the Project

Traditional diagnosis requires physical inspection by agricultural officers or sending leaf samples to laboratories, taking days or weeks during which infections spread uncontrollably. Recent advances in Convolutional Neural Networks (CNNs) have enabled accurate visual feature extraction from leaf surfaces. By coupling cloud computer vision APIs with responsive web technologies (React, Node.js, Express, MongoDB), laboratory-grade diagnostics can be brought directly to rural farmers.

1.3 Motivation

The motivation arises from the urgent need to bridge the gap between detection and action. Existing applications stop at outputting disease names without treatment guidance, leading to pesticide guesswork, high input costs, and environmental degradation. Providing actionable organic and chemical remedies protects crop yields and supports sustainable farming.

1.4 Problem Statement

“To design and develop a full-stack web application using Deep Learning Artificial Intelligence to address agricultural foliar disease identification by providing instant species classification, disease diagnosis, and structured organic and chemical remedy recommendations to farmers and agronomists.”

1.5 Objectives of the Project
  • To study existing disease diagnosis methods and computer vision architectures.
  • To design a mobile-responsive, intuitive user interface for farmers.
  • To integrate the Plant.id API v3 for high-accuracy leaf pathology detection.
  • To implement an intelligent matching engine linking diagnoses to curated remedies.
  • To evaluate system accuracy, response times, and security through comprehensive automated testing.
1.6 Scope of the Project

Covers 7 key crops (Tomato, Potato, Apple, Grape, Corn, Pepper, Strawberry) and 31+ distinct diseases and nutritional disorders, offering dual-track organic and chemical remedy plans on all modern browsers.

1.7 Organization of the Report

The report is structured into 10 chapters covering literature analysis, system architecture, AI implementation, database design, hardware/software specifications, testing results, and future enhancements.

CHAPTER 2: EXISTING SYSTEM AND PROBLEM ANALYSIS
2.1 Overview of the Existing System

In the current agricultural landscape, crop disease identification relies primarily on manual visual inspection by farmers, informal consultation with pesticide shopkeepers, or physical visits by agricultural extension officers.

2.2 Working of the Existing System

When a farmer observes leaf yellowing or spots, they either consult local fertilizer dealers—who often prescribe expensive broad-spectrum chemicals—or submit samples to agricultural research centers, which entails turnaround times of 7 to 14 days.

2.3 Limitations of the Existing System
  • Diagnostic Inaccuracy: Different pathogens produce overlapping visual symptoms that are frequently misidentified by visual inspection.
  • Severe Time Delays: Laboratory culture reports arrive days after infections have spread across entire fields.
  • Excessive Chemical Expenses: Guesswork leads to over-spraying synthetic fungicides, raising input costs and inducing pathogen resistance.
  • Lack of Advisory in Digital Tools: Existing mobile apps output disease labels but offer no structured recovery plans.
2.4 Literature Review

Mohanty et al. (2016) demonstrated 99.35% classification accuracy on 54,306 leaf images using CNNs (PlantVillage dataset), proving deep learning's efficacy in mobile diagnostics. Hughes & Salathé (2015) highlighted the necessity of accessible computer vision to replace slow laboratory cultures.

CHAPTER 3: PROPOSED SYSTEM
3.1 Introduction & 3.2 Overview of the Proposed System

The proposed system is a full-stack Single Page Application (SPA) that accepts leaf photographs, performs deep-learning computer vision analysis, resolves diagnoses against a curated agricultural knowledge base, and outputs comprehensive agronomic recovery advisories.

3.3 Proposed System Architecture

The architecture follows a decoupled three-tier model: React 18 + Vite on the presentation layer, Node.js + Express.js on the application layer, and MongoDB for persistence, integrated with the external Plant.id AI API over secure HTTPS.

3.4 Major Features
  • Drag-and-Drop Uploader: Client-side preview, file type enforcement, and progress tracking.
  • Deep Vision Analysis: Instant species identification, disease classification, and confidence scoring.
  • Actionable Dual Advisory: Clear separation into Organic Remedies, Chemical Treatments, Symptoms, and Causes.
  • Scan History & Analytics: Longitudinal tracking of recurring crop infections with visual analytics.
  • Admin Portal: Role-based access control for dynamic knowledge base updates without code modification.
3.5 Functional Requirements
  • The system shall accept JPG, JPEG, and PNG leaf images up to 5 MB.
  • The system shall validate image magic bytes to prevent malicious non-image file uploads.
  • The system shall authenticate users with signed stateless JSON Web Tokens.
  • The system shall query the AI engine and return diagnosis and confidence scores.
  • The system shall display organic remedies, chemical treatments, and prevention checklists.
3.6 Non-Functional Requirements

Performance: Inference turnaround within 2 to 4 seconds. Security: 12-round Bcrypt password hashing and JWT token expiration. Usability: Responsive layout supporting mobile, tablet, and desktop viewports.

CHAPTER 4: ARTIFICIAL INTELLIGENCE COMPONENTS USED
4.1 Introduction to Artificial Intelligence in Agriculture

Artificial Intelligence—specifically Deep Learning Computer Vision using Convolutional Neural Networks (CNNs)—has revolutionized plant pathology. CNNs autonomously extract hierarchical visual features such as chlorosis, necrotic lesion patterns, and fungal pustules from leaf pixels, outperforming traditional manual heuristics.

4.2 AI Model Used

The project integrates the Plant.id API v3, developed by FlowerChecker s.r.o. The underlying architecture uses multi-task deep convolutional neural networks trained on over 30 million botanical and phytopathological images, capable of dual-task classification: taxonomic species identification and foliar disease probability estimation.

4.4 Payload Engineering and Design

Computer vision services require precisely structured parameter configurations. In plantIdService.js, payloads are structured to ensure both species identification and ranked disease probabilities are extracted simultaneously:

{ images: [base64String], health: "all", classification_level: "species" }

This payload instructs the vision model to analyze overall plant health, restrict botanical suggestions to the species level, and return empirical confidence ratings for every detected anomaly.

4.5 Workflow of the AI Component
  1. User submits a leaf photo via the React interface.
  2. The application validates MIME type and file size constraints on the client.
  3. Express backend receives image buffer into RAM and validates magic bytes.
  4. Backend encodes buffer into Base64 and dispatches secure HTTPS POST request.
  5. Plant.id CNN vision models infer features, returning species taxonomy and disease probabilities.
  6. Backend validates the is_plant binary flag; if false, it cleanly prompts the user.
  7. diseaseMatchService resolves top-1 disease suggestion against MongoDB catalogue records.
  8. The application processes the result and displays diagnosis and complete remedy cards.
4.6 Model Parameters and Configuration
  • Endpoint: https://api.plant.id/v3/identification
  • HTTP Method: POST with Api-Key authentication header
  • Classification Level: species
  • Health Assessment: all (returns health status + disease suggestions)
  • Timeout: 45,000 ms (handles high-latency rural mobile internet)
4.7 AI Output Validation

To prevent incorrect responses: (1) Non-plant images are detected via result.is_plant.binary === false and rejected with an HTTP 400 prompt. (2) Confidence scores below 70% are automatically flagged as low_confidence with a recommendation to upload clearer lighting. (3) Outages and missing keys return friendly 503 status codes rather than invented fallback results.

4.8 Responsible AI Considerations

Leaf images contain zero personal data, ensuring privacy. The secret API key is isolated server-side. Every diagnosis includes an agronomic disclaimer encouraging local label compliance before spraying concentrated chemicals.

4.9 Role of AI in the Project

AI performs visual sensory classification (species and pathology identification from pixels), while conventional programming handles authentication, rate limiting, knowledge base matching, and database persistence.

CHAPTER 7: IMPLEMENTATION
7.1 Introduction & 7.2 Project Structure

The implementation translates architectural designs into a working software application structured cleanly into frontend/ (React components, hooks, services) and backend/ (controllers, middleware, models, services).

7.3 Implementation of Modules
  • Authentication: authController.js issues JWT tokens; authMiddleware.js verifies incoming Bearer tokens.
  • Upload & Validation: uploadMiddleware.js parses multipart requests into RAM and checks JPEG (FF D8 FF) / PNG (89 50 4E 47) magic bytes.
  • AI Integration: plantIdService.js encodes image buffers to Base64 and dispatches HTTPS identification requests.
  • Disease Matcher: diseaseMatchService.js performs case-insensitive taxonomic lookups in MongoDB.
7.4 AI Model Integration & 7.5 API Implementation

The integration connects directly to the Plant.id v3 endpoint via Axios, passing Base64 image payloads and setting health: 'all'. The returned JSON is mapped into internal objects containing crop species, disease name, and confidence percentages.

7.6 Database Implementation & 7.7 UI Implementation

Mongoose models (User, Disease, Prediction) enforce schema constraints. The React UI uses Tailwind CSS, Lucide icons, and Chart.js for real-time history visualizations.

7.8 Error Handling, 7.9 Deployment & 7.10 Repository

Errors are caught via centralized errorMiddleware.js. Local deployment requires starting MongoDB, running npm run dev in backend/, and running npm run dev in frontend/. Source code is tracked in a clean Git repository with credentials isolated in .env files.
